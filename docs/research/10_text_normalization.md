# 日本語G2P テキスト正規化処理 調査レポート

## 1. 概要

日本語G2P（Grapheme-to-Phoneme）において、テキスト正規化（Text Normalization）は入力テキストを音声合成可能な読み仮名に変換する前処理である。数字、記号、英字、日付、住所など、辞書だけでは読みが確定しない表記を適切な読み仮名に変換する。

### 処理パイプライン上の位置づけ

OpenJTalkのNJD（日本語ルール処理）では、以下の順序で処理される:

1. **njd_set_pronunciation** - 辞書にない仮名やアルファベットの読みを生成
2. **njd_set_digit** - 二桁以上の数字や助数詞・単位の読みを生成
3. **njd_set_accent_phrase** - アクセント句の結合
4. **njd_set_accent_type** - アクセント核位置の決定
5. **njd_set_unvoiced_vowel** - 無声音化処理
6. **njd_set_long_vowel** - 長音化処理（例:「エイ」→「エー」）

テキスト正規化は主にステップ1〜2で処理される。

### 2.4 助数詞の読み変換

助数詞（カウンター）は日本語TTSで最も複雑な正規化処理の一つ。数字と組み合わさると、促音便・連濁・半濁音化が発生する。

#### 2.4.1 促音便ルール

助数詞がカ行・サ行・タ行・ハ行で始まる場合、「1・6・8・10・100」で促音便が発生する。

| 数字 | +個(コ) | +本(ホン) | +杯(ハイ) | +匹(ヒキ) | +回(カイ) |
|------|---------|----------|----------|----------|----------|
| 1 | イッコ | イッポン | イッパイ | イッピキ | イッカイ |
| 2 | ニコ | ニホン | ニハイ | ニヒキ | ニカイ |
| 3 | サンコ | サンボン | サンバイ | サンビキ | サンカイ |
| 4 | ヨンコ | ヨンホン | ヨンハイ | ヨンヒキ | ヨンカイ |
| 5 | ゴコ | ゴホン | ゴハイ | ゴヒキ | ゴカイ |
| 6 | ロッコ | ロッポン | ロッパイ | ロッピキ | ロッカイ |
| 7 | ナナコ | ナナホン | ナナハイ | ナナヒキ | ナナカイ |
| 8 | ハッコ | ハッポン | ハッパイ | ハッピキ | ハッカイ |
| 9 | キュウコ | キュウホン | キュウハイ | キュウヒキ | キュウカイ |
| 10 | ジュッコ | ジュッポン | ジュッパイ | ジュッピキ | ジュッカイ |

#### 2.4.2 連濁（濁音化）ルール

数詞が「ん」で終わる場合（3・千・万・何）、ハ行で始まる助数詞が濁音化する。

| 助数詞 | 3+ | 千+ | 万+ | 何+ |
|--------|-----|------|------|------|
| 本(ホン) | サンボン | センボン | マンボン | ナンボン |
| 匹(ヒキ) | サンビキ | センビキ | マンビキ | ナンビキ |
| 杯(ハイ) | サンバイ | センバイ | マンバイ | ナンバイ |
| 百(ヒャク) | サンビャク | - | - | ナンビャク |

#### 2.4.3 半濁音化ルール

「1・6・8・10」とハ行助数詞で半濁音化が発生する。

| 助数詞 | 1+ | 6+ | 8+ | 10+ |
|--------|-----|------|------|------|
| 本(ホン) | イッポン | ロッポン | ハッポン | ジュッポン |
| 匹(ヒキ) | イッピキ | ロッピキ | ハッピキ | ジュッピキ |
| 杯(ハイ) | イッパイ | ロッパイ | ハッパイ | ジュッパイ |
| 百(ヒャク) | イッピャク | ロッピャク | ハッピャク | - |

### 2.5 小数・分数の読み

**小数:**
- `3.14` → サンテンイチヨン（桁ごとに読む）
- 小数点は「テン」と読む
- 小数部は各桁を個別に読み上げる

**分数:**
- `1/3` → サンブンノイチ（分母→「ブンノ」→分子）
- `2/5` → ゴブンノニ

### 2.6 電話番号の読み

電話番号は各桁を個別に読む:
- `090-1234-5678` → ゼロキュウゼロ ノ イチニサンヨン ノ ゴロクナナハチ

電話番号特有の読み:
| 数字 | 電話番号読み |
|------|------------|
| 0 | ゼロ/レイ |
| 1 | イチ |
| 2 | ニー |
| 3 | サン |
| 4 | ヨン |
| 5 | ゴー |
| 6 | ロク |
| 7 | ナナ |
| 8 | ハチ |
| 9 | キュウ |

**処理の優先順位（Livetoon TTSの知見）:**
1. 電話番号パターン（各桁読み）を最初に処理
2. 大数（万・億・兆）パターン
3. 年号パターン
4. 時刻パターン

この順序を守らないとパターンが干渉する。

### 2.7 その他の数字パターン

**郵便番号:**
- `123-4567` → イチニサン ノ ヨンゴロクナナ

**番号一般:**
- 部屋番号、型番等 → 各桁読み
- `Room 301` → サンマルイチ（ゼロを「マル」と読むことも）

## 6. 住所表現の読み

### 6.1 基本構造

住所は以下の階層で構成される:
```
都道府県 + 市区町村 + 町名 + 丁目 + 番地 + 号
```

### 6.2 住所固有の読み

| 表記 | 読み |
|------|------|
| 丁目 | チョウメ |
| 番地 | バンチ |
| 番 | バン |
| 号 | ゴウ |
| 町 | チョウ/マチ（地名依存） |
| 村 | ソン/ムラ（地名依存） |

### 6.3 住所の数字読み

住所中の数字は通常の桁読み:
- `2丁目1番1号` → ニチョウメ イチバン イチゴウ
- `2-1-1` → ニ ノ イチ ノ イチ

### 6.4 処理上の課題

- 地名（町名・字名）は辞書依存。固有名詞辞書が必要
- 同じ漢字でも地域により読みが異なる（例:「町」→チョウ/マチ）
- Amazon Pollyでは`<phoneme>`タグで明示的に読みを指定する必要があるケースが多い

## 7. OpenJTalkのnjd_set_digit実装詳細

### 7.1 処理概要

`njd_set_digit`は形態素解析後のNJDノード列に対して、数字列を桁読みに変換する処理を行う。

例: `3939`（形態素「さん」「きゅう」「さん」「きゅう」）→ `さんぜんきゅうひゃくさんじゅうきゅう`

### 7.2 jpreprocessでの実装構造

jpreprocess（Rust）での実装は以下のモジュールで構成:

```
crates/jpreprocess-njd/src/open_jtalk/
  digit/
    mod.rs              -- メインロジック
    lut/
      mod.rs            -- ルックアップテーブル共通
      numeral.rs        -- 数字・桁の変換テーブル
      class1.rs         -- 数字側の読み変化ルール
      class2.rs         -- 助数詞側の濁音/半濁音変化
      class3.rs         -- 和語数詞変換（ヒト・フタ等）
      others.rs         -- 特殊変換（人、日、日間）
  digit_sequence/
    mod.rs              -- 数字列の解析
    builder.rs          -- 数字列の構築
    score.rs            -- スコアリング
```

### 7.3 処理フロー（4段階）

1. **小数点処理**: 「．」「・」の前後の数字を特別処理（各桁読み）
2. **助数詞変換（Class1・2）**: 単一の助数詞を持つ数字の読みを変更
3. **複合数字変換（Class3・numeral）**: 2つ以上の要素を持つ数字を処理
4. **日付特殊処理**: 「一日」→「ツイタチ」等の特殊パターン対応

### 7.4 ルックアップテーブルの構造

**DIGIT_CONVERSION_TABLE:**
- 「百」の場合: 「六」→ロッ、「八」→ハッ
- 「千」「兆」の場合: 「一」→イッ、「八」→ハッ、「十」→ジュッ

**NUMERATIVE_CONVERSION_TABLE:**
- 「百」「千」に後続する助数詞の濁音化・半濁音化を制御
- 「三」「何」→濁音化、「六」「八」→半濁音化

**NUMERAL_LIST4（基本数字）:**
- 「一」〜「九」、「何」「幾」

**NUMERAL_LIST5（単位）:**
- 「十」「百」「千」「万」「億」「兆」「京」「垓」等の大数単位

## 8. 他のTTSシステムでのテキスト正規化手法との比較

### 8.1 OpenJTalk方式

- **アプローチ**: ルールベース（手動定義のテーブルとロジック）
- **処理位置**: 形態素解析後のNJD処理内
- **特徴**: 日本語の暗黙ルールをコード化。完全なルール集ではないが実用的
- **限界**: 未知の助数詞やパターンに対応困難

### 8.2 Livetoon TTS方式

- **アプローチ**: ハイブリッド（Misaki + Sudachi）+ 正規表現
- **処理順序**: 電話番号→大数→年号→時刻の優先順位で処理
- **特徴**: 文脈依存の読み分けを正規表現パターンで実現
- **精度**: 90.9%（エンタメ・ビジネスドメイン）

### 8.3 Amazon Polly方式

- **アプローチ**: 深層学習モデル + SSMLによる明示的制御
- **SSML対応**: `<say-as interpret-as="digits/cardinal/ordinal">`で読み方を制御
- **特徴**: `x-amazon-pron-kana`属性で発音仮名を直接指定可能
- **限界**: 住所などの固有名詞は手動チューニングが必要

### 8.4 Google Cloud TTS方式

- **アプローチ**: ニューラルネットワーク + SSMLサポート
- **SSML対応**: `<say-as>`タグで数字・日付等の読み方を指定
- **特徴**: Chirp 3 HDでSSML完全サポート（phoneme, say-as等）
- **日本語対応**: ja-JPロケール対応

### 8.5 VOICEVOX方式

- **アプローチ**: OpenJTalkベースのフロントエンド
- **テキスト処理**: OpenJTalkでアクセント句を生成→ピッチ・長さ推定→波形合成
- **特徴**: OpenJTalkの正規化処理をそのまま活用

### 8.6 比較まとめ

| システム | 正規化方式 | 辞書依存 | カスタマイズ性 | 精度 |
|---------|-----------|---------|-------------|------|
| OpenJTalk | ルールベース | 高（naist-jdic） | テーブル編集 | 中〜高 |
| Livetoon | ハイブリッド | 中（Sudachi） | 正規表現 | 高（90.9%） |
| Amazon Polly | DL+SSML | 低 | SSML制御 | 高 |
| Google Cloud | NN+SSML | 低 | SSML制御 | 高 |
| VOICEVOX | OpenJTalk | 高 | 辞書追加 | 中〜高 |

## 9. 正規化ルール一覧（実装用）

### 9.1 前処理（Unicode正規化）

```
1. NFKC正規化の適用
2. 全角数字 → 半角数字 (０-９ → 0-9)
3. 全角英字 → 半角英字 (Ａ-Ｚ → A-Z, ａ-ｚ → a-z)
4. 半角カタカナ → 全角カタカナ (ｱ-ﾝ → ア-ン)
5. 全角記号の正規化 (＋→+, ％→% 等)
```

### 9.2 数字正規化ルール（処理優先順位順）

```
優先度1: 電話番号パターン
  正規表現: \d{2,4}[-ー]\d{2,4}[-ー]\d{3,4}
  処理: 各桁を個別に読み上げ

優先度2: 郵便番号パターン
  正規表現: \d{3}[-ー]\d{4}
  処理: 各桁を個別に読み上げ

優先度3: 日付パターン
  正規表現: (\d{1,4})年(\d{1,2})月(\d{1,2})日
  処理: 年→桁読み+ネン、月→月名テーブル、日→日名テーブル

優先度4: 時刻パターン
  正規表現: (\d{1,2})時(\d{1,2})分
  処理: 時→ジ、分→プン/フン（音便）

優先度5: 小数パターン
  正規表現: (\d+)[\.．](\d+)
  処理: 整数部→桁読み + テン + 小数部→各桁読み

優先度6: 分数パターン
  正規表現: (\d+)[/／](\d+)
  処理: 分母→桁読み + ブンノ + 分子→桁読み

優先度7: 助数詞付き数字
  正規表現: (\d+)(個|本|人|匹|杯|回|枚|台|冊|...)
  処理: 桁読み + 助数詞変換テーブル参照

優先度8: 一般数字（桁読み）
  正規表現: [\d,，]+
  処理: カンマ除去後、桁読み変換
```

## 10. 実装上の推奨事項

### 10.1 処理順序

1. **Unicode正規化**（NFKC）
2. **全角半角統一**
3. **パターンマッチによる数字正規化**（優先度順に処理）
4. **記号の読み変換**
5. **英字の読み変換**（辞書→略語テーブル→アルファベット読み）
6. **形態素解析**（MeCab/NMeCab）
7. **NJD処理**（数字桁読み、助数詞変換、アクセント処理）

### 10.2 形態素解析との連携

OpenJTalk方式では、形態素解析の結果に対してnjd_set_digitが動作する。つまり:
- 形態素解析の段階で数字は辞書の読みが付与される
- njd_set_digitでは、連続する数字形態素を桁読みに再構成する
- 助数詞との結合も形態素レベルで処理される
